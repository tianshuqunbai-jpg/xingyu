# 星语核心第一阶段只读复核

范围：`core-review.diff` 涉及的请求、单轮、长期记忆逻辑，以及它们与当前 `storage.js`、`ChatPage.jsx` 的接点。对照 `2026-09-30-starvox-upgrade-design.md` 第一阶段。实施记录中的 9/9 测试结果已阅；本次未重复运行测试，也未读取真实浏览器数据。

## 发现（按严重度）

### P1 — “彻底清除”仍可被其他人格的记忆任务写回

`src/lib/storage.js:66-72` 调用无参 `cancelPendingExtraction()` 后删除全部人格分区；但 `src/lib/memory.js:1193-1205` 的无参语义已改为只取消当前人格。若人格 B 有待执行或正在执行的提炼、当前作用域为 A，彻底清除后 B 的任务仍会写回 `memory::B`。若隐私锁也同时被删除，写回还会变成明文。应提供并在 `clearAllData` 调用“取消全部人格任务”的明确接口，并使所有在途结果失效；保留无参“只取消当前人格”的现有语义。补充 A/B 双人格、B 在途、彻底清除后无任何分区复活的回归场景。

### P1 — 重建与关键词补全未参加清空世代控制

队列提炼在 `src/lib/memory.js:1154-1156` 检查世代，但 `rebuildMemoryFromMessages` 在 `src/lib/memory.js:1472-1476` 直接调用默认 `isCurrent: () => true` 的 `extractPairsChunk`；清空记忆期间，晚到的重建结果会由 `src/lib/memory.js:1069-1077` 再次写入。`backfillKeywords` 在 `src/lib/memory.js:1315-1318` 拿到整份旧快照，等待网络后于 `:1396` 覆盖保存；清空或其他新增事实发生在等待期间，也会被旧快照复活或覆盖。两条长任务均应捕获固定人格及其世代，网络返回后先验证；补全只按仍存在的事实 ID 合并关键词，避免整库覆盖。分别覆盖“清空时重建返回”和“清空/新增时补全返回”。

### P1 — 已加密的旧全局记忆迁移会得到空分区

`src/lib/memory.js:388-399` 从 `localStorage` 直接读取旧全局 key，把加密信封字符串再交给 `writeSecure` 写进新分区；`readMemoryRaw` 随后在 `:416-423` 将解密结果解析成信封对象，`sanitizeMemory` 因没有 `facts` 等字段而得到空记忆。此时迁移标记已经写入，旧记录虽保留却不会再被自动认领。迁移应经 `readSecure(STORAGE_KEYS.memory)` 取得明文并验证记忆结构，再写入、回读验证后标记完成；锁定状态应推迟迁移，绝不能把原始加密信封当记忆 JSON。

### P2 — 本地问候仍进入 API 历史

`src/components/ChatPage.jsx:263-267` 和 `:443` 把人格问候标成 `local: true`；`src/lib/turn.js:66-69` 只排除 `status === 'local'`，没有排除布尔 `m.local`。因此首次发言时问候作为一条 assistant 历史发给 API，违背“仅本地消息不进入 API 历史”。在历史谓词中同时排除 `m.local`，并用真实问候结构增加回归断言。

### P2 — 重建来源缺失会话 ID，稳定出处退化为旧下标

核心接口 `src/lib/memory.js:1446-1456` 支持固定 `personalityId`、`sessionId`，但 `src/components/ChatPage.jsx:887-893` 两者都没有传。现代消息虽有稳定 `messageId`，却失去会话边界；遇到没有消息 ID 的旧存档时，事实只剩数字 `turn` 和空 `sessionId`。`src/lib/turn.js:284-289` 对空会话 ID 不限制匹配，此时在另一会话同一下标的用户消息可能被误当出处。调用时应传入确认重建时的固定会话和人格；旧备份确实没有消息 ID 时才走受限的 `turn` 兼容路径。切换会话/人格期间完成重建也应仍落在原目标。

### P2 — 敏感轮次只按用户文本标记，含蓄摘要可能外泄

`src/lib/memory.js:1117-1123` 的提炼隐私标记只结合传入 `sensitive` 与用户文本；`src/components/ChatPage.jsx:339-342` 只传用户标记。若普通用户提问引出明显私密的助手回复，模型提炼的 `summary` 不含敏感关键词，`src/lib/memory.js:653-655` 会将其保存为非敏感，随后在亲密模式关闭时由 `:956-957` 注入提示词。应把助手原文也纳入轮次判定，并在摘要/事实入库时应用同一私密判定与轮次标签；用“普通问句、私密回复、含蓄摘要”回归验证。

### P2 — 合法的多行 SSE `data:` 帧被误判为流格式错误

`src/lib/deepseek.js:196-207` 将每一行 `data:` 独立 `JSON.parse`，`src/lib/deepseek.js:228-231` 也仅按换行拆分。SSE 允许一个事件包含多行 `data:`，其内容需按事件空行合并；JSON 跨两行时第一行解析失败，流被提前终止。应按空行划分事件、合并同一事件的 `data:` 行后解析，并兼容 CRLF、注释行及 `[DONE]`，补一个分块到达的合法多行帧用例。

## Spec 结论

第一阶段尚未完全符合规范。单轮当前输入去重、成功终态与失败情绪隔离、停止/超时的晚回调隔离、普通队列按人格/会话/世代绑定，在现有实现与 9 个合成测试中有相应证据。上述 P1/P2 场景仍破坏“清空后不复活”“旧存档兼容迁移”“仅本地消息不进历史”“私密过滤一致”和稳定出处。`storage.js` 正在由其他实现者集成；`clearAllData` 接口不匹配属于已观察到的跨模块接点，不等同于认为存储工作已完成。

## Quality 结论

核心代码总体有清晰的终态与任务边界，但异步写入的保护只覆盖常规提炼队列，没有覆盖同样能写记忆的重建和补全。建议实现者优先修复三个 P1，再补 P2 的接口调用、隐私与 SSE 用例；现有 9/9 测试没有覆盖这些触发条件，不能据此判为已通过全部第一阶段验收。
